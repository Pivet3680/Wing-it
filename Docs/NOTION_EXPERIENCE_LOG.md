# Notion 개발 경험 기록 가이드

> **기록 페이지:** [Wing it! 개발 경험 로그](https://app.notion.com/p/40d5b2301d4581e2966de9d792a880de?pvs=204) — Notion의 `Wing it !` 페이지 아래에 만든 목차·안내용 페이지.
> **기록 방식:** 의미 있는 작업 세션마다 이 로그 페이지의 하위 페이지를 하나 만든다. 로그 페이지 본문에 세션 내용을 누적하지 않는다.

## 1. 목적과 기록 단위

개발 과정에서 다시 참고하거나 이력으로 활용할 가치가 있는 경험을 기록한다. **의미 있는 작업 세션 하나를 로그 페이지 아래의 하위 페이지 하나로 만든다.** 세션에 경험이 여러 개 있어도 한 하위 페이지에 묶고, 주요 경험은 최대 5개로 제한한다. 제목은 `YYYY-MM-DD — 핵심 주제` 형식으로 작성한다. 날짜를 확인할 수 없으면 추측하지 않고 주제만 쓴다.

`개발 경험 로그` 페이지는 목차와 안내용으로 유지한다. 개별 세션 내용은 반드시 그 아래에 새 하위 페이지로 작성하며, 이전 기록은 덮어쓰지 않는다.

## 2. 기록할 경험

### 기록 후보

- Unity·C# 구현 중 의미 있는 기술 역량, 엔진 활용, 구조 설계
- 원인 분석·재현·수정·검증이 확인되는 문제 해결
- 대안 비교, 트레이드오프, 시행착오가 드러나는 기술적 판단
- API 계약, Git 협업, 역할 분담, 팀·AI 에이전트 조율 개선
- Codex·MCP·자동화·프롬프트·작업 위임으로 결과나 워크플로우를 개선한 사례
- AI 오판·요구 오해·과잉 분석·불필요한 작업·반복 지시·지연·결과 불만족 등 개선할 가치가 있는 애로사항

### 제외

- 단순 기능 구현, 기본적인 Git 사용, 일반 문서 작성처럼 흔하고 회고 가치가 낮은 작업
- 배울 점이나 확인 가능한 결과가 없는 일상 작업
- 계획·제안을 실제 수행 또는 완료 경험으로 서술하는 내용
- 원인이 불분명한 문제의 책임을 사용자나 AI에게 추측해 돌리는 내용

기록 가치가 없으면 새 하위 페이지를 만들지 않는다. 내용을 채우기 위해 경험이나 성과를 만들어내지 않는다.

## 3. 근거와 표현 원칙

- 경험 본문은 **현재 작업 세션의 대화만** 근거로 한다. 다른 세션·메모리·외부 자료로 내용을 보충하거나 교차 검증하지 않는다.
- 로그 페이지의 기존 하위 페이지는 중복 확인에만 사용한다. 과거 내용에서 현재 경험의 사실을 가져오지 않는다.
- 계획·제안·시도·실제 수행·완료·검증을 구분한다. 검증하지 않은 결과는 성공으로 쓰지 않는다.
- 사용자의 판단·지시·수정과 AI가 수행한 일을 분리한다.
- 날짜·시간은 현재 세션에서 확인되는 범위까지만 적는다. 알 수 없는 값은 `미확인` 또는 공란으로 두고 추측하지 않는다.
- 지연 시간, 토큰 비용, 성능 수치 등 대화에 근거가 없는 숫자는 만들지 않는다.
- AI 애로사항은 불만·오류·재작업이 대화에서 확인될 때만 적는다. 원인이 분명하지 않으면 추측하지 않는다.

## 4. 하위 페이지 본문과 분량

각 하위 페이지는 한국어 Markdown으로 **500~700자 내외**를 목표로 한다. 해당 내용이 없는 항목은 생략한다.

```md
## 세션 요약
- 기간:
- 주제:

## 주요 개발 경험
### 1. 발생 일시 — 유형 및 제목
- 문제·상황:
- 판단·행동·결과:
- 기술 스택·협업·AI 워크플로우:

## AI 활용 애로사항 (해당할 때만)
- 발생 일시:
- 문제·불만족:
- 원인: 요청 범위 과도·모호·과도한 제약 / AI 과잉 분석·검증 / AI 오판·요구 오해 / 부적절한 모델 선택 / 기타
- 영향:
- 대응·개선:

## 미해결 사항 (중요한 내용만)
- 내용:
```

## 5. 하위 페이지 작성 절차

1. 현재 세션에 기록 가치가 있는 경험이 있는지 선별한다. 가치가 없으면 Notion을 수정하지 않는다.
2. 고정된 `개발 경험 로그` 부모 페이지의 하위 페이지 목록에서 현재 세션과 중복되는 기록이 있는지 확인한다. 중복 확인은 제목·날짜·세션 링크에 한정한다.
3. 중복이 없으면 부모 페이지를 `parent`로 지정해 새 하위 페이지를 만든다. 부모 로그 페이지에 본문을 추가하거나 매번 `Wing it !` 최상위 페이지에 직접 새 페이지를 만들지 않는다.
4. 새 하위 페이지 제목은 날짜가 확인되면 `YYYY-MM-DD — 핵심 주제`로 작성한다. 내용은 위 템플릿을 따른다.
5. 페이지가 로그 부모 아래 생성되었는지, 본문이 저장되었는지 확인한다. 기존 기록은 수정하거나 덮어쓰지 않는다.
6. 페이지 생성에 실패하면 완료된 것처럼 말하지 않는다. 실패 원인과 필요한 조치를 보고한다.

## 6. 기록이 없거나 생성하지 못한 경우

- 기록 가치가 없으면 빈 페이지를 만들지 않는다. 사용자가 세션 기록을 요청하면 `기록할 주요 개발 경험 없음`이라고 답한다.
- Notion 연결이나 쓰기 권한 문제로 기록하지 못하면 그 사실을 알린다. 자동으로 로컬 파일을 대신 만들지 않는다.
- 성공적으로 기록했다면 최종 작업 보고에 새 하위 페이지의 링크와 기록 주제를 간단히 포함한다.
