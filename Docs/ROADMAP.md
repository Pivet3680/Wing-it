# Wing it! — 개발 로드맵

> **문서 상태:** 초기 개발 계획
> **기획 기준:** [`GDD.md`](GDD.md)
> **현황 기준일:** 2026-11-03
> **상태 원칙:** 실제 프로젝트에서 확인한 근거만 진행 현황에 반영한다. 씬 파일의 존재만으로 실행 가능 여부나 기능 구현을 단정하지 않는다.

## 1. 목적과 운영 원칙

이 문서는 개발 순서, 우선순위, 단계별 완료 조건과 진행 상태를 관리한다. 첫 목표는 자동 전진 중 **반복 상승·고속 활공·조준·사격·회피**를 연속해서 경험할 수 있는 짧은 플레이 가능 프로토타입이다.

- 핵심 조작을 먼저 구현하고 검증한다.
- 한 번에 많은 기능을 추가하기보다 작은 단위로 작업하고 관련 동작을 확인한다.
- GDD의 `미정` 또는 `검토 중`인 규칙을 임의로 확정하지 않는다. 임시값은 테스트용임을 표시한다.
- 일정과 출시일은 정하지 않는다. 검증 결과에 따라 범위와 순서를 조정한다.
- 기획된 기능과 실제 구현·검증된 기능을 구분한다.

### 상태 표기

| 상태 | 의미 |
| --- | --- |
| 미확인 | 프로젝트 상태를 아직 조사하지 않음 |
| 예정 | 필요한 작업을 확인했으나 시작하지 않음 |
| 진행 중 | 작업에 착수했으나 단계 완료 조건을 충족하지 않음 |
| 검증 대기 | 구현은 되었으나 필요한 검증이 남아 있음 |
| 완료 | 완료 조건을 충족하고 필요한 검증 근거를 확인함 |
| 보류 | 사유를 기록하고 현재 범위에서 제외함 |

체크박스는 **개별 조사·작업 항목의 수행 여부**를 나타낸다. 체크된 항목이 있어도 단계 완료 조건과 필수 검증을 충족하지 않았다면 단계 상태를 `완료`로 바꾸지 않는다. 검증하지 못한 항목은 `미검증`으로 보고하며, 필수 검증이 남아 있으면 완료 처리하지 않는다. 테스트 방법과 판정 기준은 [`TESTING.md`](TESTING.md)에서 관리한다.

## 2. 개발 단계 개요

| 단계 | 우선순위 | 핵심 목표 | 현재 상태 |
| --- | --- | --- | --- |
| 0. 프로젝트 현황 확인 | 최우선 | Unity 프로젝트, 씬, 기존 구현 상태 파악 | 진행 중 |
| 1. 이동과 비행 | 최우선 | 자동 전진, 지상 이동, 중력, 반복 상승, 활공 | 진행 중 |
| 2. 조준과 사격 | 높음 | 마우스 조준, 기본 무기, 공격 판정 | 미확인 |
| 3. 장애물·적·테스트 구간 | 높음 | 회피와 전투를 연결한 짧은 플레이 | 미확인 |
| 4. 핵심 조작 검증 및 개선 | 최우선 | 조작성·재미 확인과 필요한 수정 | 미확인 |
| 5. 확장 시스템 검토 | 후순위 | 증강, 스테이지·보스, 아이템 등 구체화 | 미확인 |

단계는 권장 순서다. 검증 결과에 따라 이전 단계로 돌아가거나 순서를 조정할 수 있다.

## 3. 단계별 작업 계획

### 단계 0. 프로젝트 현황 확인

**목표:** 이미 만들어진 부분과 미구현·미확인 부분을 구분하고 안전한 개발 출발점을 확보한다.

- [x] `ProjectSettings/ProjectVersion.txt`에서 Unity 버전 확인: `6000.3.21f1`
- [x] 씬 파일 존재 확인: `Assets/Scenes/SampleScene.unity`
- [ ] 시작 씬 설정과 씬의 실제 실행 가능 여부 확인
- [x] 주요 씬 오브젝트, 스크립트와 기존 구현 확인: `SampleScene`은 기본 카메라·조명·볼륨만 포함
- [x] 입력 시스템, 물리 방식, 카메라 구조와 필수 패키지 확인: 새 Input System, 3D Rigidbody, URP
- [x] 컴파일 상태와 콘솔 오류 확인: 이동 프로토타입 컴파일 성공, Console 오류 0건
- [ ] GDD 핵심 기능별 현재 구현 상태를 이 문서에 반영

**완료 조건:** 프로젝트에서 확인한 사실과 미확인 사항을 구분하고, 이후 작업에 영향을 주는 주요 오류와 위험을 기록한다.

> `SampleScene`은 기본 씬이다. 별도의 `WingItMovementPrototype` 씬에서 이동 기능을 시험했다. 시작 씬 설정은 별도로 확인하지 않았다.

### 단계 1. 이동과 비행

**목표:** 자동 전진 중 지상과 공중을 오가며 고도와 속도를 조절하는 핵심 조작을 구현하고 확인한다.

- [x] 횡스크롤 화면에서 자동 전진의 체감 구현: 플레이어 월드 이동과 카메라 추적
- [x] 지상 이동과 중력에 따른 하강 구현: 시험용 바닥과 3D Rigidbody
- [x] `Space`를 짧게 눌렀다 놓을 때 반복 상승 구현: Play Mode에서 손을 뗀 뒤 상승 확인
- [x] `Space` 긴 입력에 의한 낮은 점프, 하강 완화와 전진 가속 구현: Inspector에서 두 점프 높이와 활공값 조절 가능
- [x] 순간 상승과 활공의 입력 전환 방식 시험: 짧은 입력 해제 시 일반 점프, 긴 입력에서는 낮은 점프 후 활공·해제 시 추가 상승 없음 확인
- [ ] 지면·천장 충돌과 공중 이동의 기본 예외 상황 확인

**완료 조건:** 짧은 시험 구간에서 자동 전진, 지상 이동, 반복 상승과 활공이 이어지고, 입력 구분과 기본 충돌이 의도대로 작동함을 확인한다.

**검증 질문:** 상승과 활공이 서로 구분되는 선택인가? 상승·하강·속도 변화가 직관적인가?

활공 전환 시간, 상승량, 중력과 가속량은 GDD에서 미정이다. 기본 속도의 약 1.5배는 초기 시험값 후보일 뿐 확정값이 아니다.

### 단계 2. 조준과 사격

**목표:** 이동·비행과 동시에 적을 조준하고 공격하는 기본 전투 조작을 만든다.

- [x] 마우스 방향에 따른 전방 180도 조준 표현 구현
- [x] 마우스 왼쪽 버튼으로 기본 사격 구현
- [x] 기본 도형 탄환의 생성과 전방 이동 확인
- [x] 시험용 적에 탄환 피격과 제거 적용 확인
- [ ] 지상·공중에서 사격과 이동이 함께 가능한지 직접 조작으로 확인

**완료 조건:** 이동·비행 중 마우스로 조준하고 공격할 수 있으며, 지정한 대상에 공격 판정이 적용됨을 확인한다.

**검증 질문:** 이동 중 조준이 지나치게 어렵지 않은가? 사격 피드백이 알아보기 쉬운가?

시험용 발사체, 전방 180도 제한, 버튼을 누르는 동안 간격을 둔 연사를 적용했다. 탄약과 정식 피해 규칙은 후속 검토 대상이다.

### 단계 3. 장애물·적·테스트 구간

**목표:** 이동, 회피와 사격을 하나의 짧은 플레이 흐름으로 연결한다.

- [x] 기본 지형과 지상·공중 시험용 장애물 배치
- [x] 장애물 접촉 시 플레이어 피격 색상 표시와 복구 확인
- [x] 일반 적 프리팹 한 종류와 씬 인스턴스 두 개 연결
- [x] 화면 안에서 가까워지면 접근·발사하고, 화면 밖에서는 동작 중단 후 5초 제거 구현
- [x] 적의 탄환 피격 후 제거 동작 확인
- [ ] 지상·공중의 위험을 시험할 짧은 구간 제작
- [ ] 구간을 반복 실행하며 게임 흐름 확인

**완료 조건:** 짧은 구간에서 자동 전진하며 고도를 조절해 장애물을 회피하고, 적을 조준·사격하는 플레이를 경험할 수 있다.

**검증 질문:** 장애물과 적 배치가 의미 있는 선택을 요구하는가? 이동·사격·회피가 서로 방해만 하지 않는가?

체력·사망·재도전, 적 보상과 난이도 상승 방식은 GDD에서 미정이다. 테스트에 필요한 임시 처리만 도입하고 정식 규칙으로 확정하지 않는다.

### 단계 4. 핵심 조작 검증 및 개선

**목표:** 구현 여부를 넘어 핵심 플레이가 직관적이고 반복할 가치가 있는지 평가한다.

- [ ] 자동 전진 속도와 고도 조절의 체감 확인
- [ ] 순간 상승과 고속 활공의 역할 구분 확인
- [ ] 이동 중 조준·사격의 부담과 피드백 확인
- [ ] 장애물·적 배치가 만드는 판단의 재미 확인
- [ ] 짧은 구간의 반복 플레이 의향과 불편 요소 기록
- [ ] 주요 문제 수정 후 관련 기능 재검증

**완료 조건:** [`TESTING.md`](TESTING.md)에 정의한 절차로 필수 기능을 검증하고, 핵심 플레이의 유지·조정·재설계 방향을 근거와 함께 정리한다. 재미 평가는 자동 테스트 통과만으로 대체하지 않는다.

**판단 결과:** `유지 / 조정 후 재검증 / 핵심 방식 재검토` 중 하나를 근거와 함께 기록한다. 미확정 결과를 확정된 설계 결정처럼 취급하지 않는다.

### 단계 5. 확장 시스템 검토 (후순위)

**진입 조건:** 첫 프로토타입의 핵심 조작을 검증하고 확장 방향을 정했을 때 시작한다.

- [ ] 증강의 획득·선택·효과 구조 기획 및 소규모 시험
- [ ] 스테이지 구성과 보스전 방식 구체화
- [ ] 우클릭 아이템 사용 방식 검토
- [ ] 체력, 실패·재도전, UI와 사운드 등 기본 완성도 요소 검토
- [ ] 필요에 따라 무기·장애물·적 유형 확장

**완료 조건:** 확장 시스템의 우선순위와 최소 구현 범위를 합의하고, 관련 기획과 필요한 기술 결정을 문서화한다. 이 단계 완료가 정식 게임 완성을 뜻하지는 않는다.

초기 프로토타입에서는 복잡한 증강 밸런싱, 정식 보스전, 다수의 스테이지·무기, 영구 성장, 랭킹·온라인 기능, 모바일 최적화와 수익화를 제외한다.

## 4. 현재 진행 현황

**2026-11-03 기준 확인:** 이동 시험 씬에서 자동 전진, 점프·활공, 전방 조준, 간격을 둔 연사, 적의 접근과 탄환 피격 제거를 확인했다. 조작감과 지상·공중 연속 전투 평가는 남아 있다.

| 기능 | 현재 상태 | 확인 근거 또는 다음 확인 사항 |

| 기본 사격 | 시험 구현·확인 | 버튼 유지 중 발사 간격에 따라 탄환 반복 생성, 해제 후 중단 확인 |

기능은 현재 프로젝트에서 코드·씬·에셋을 확인하기 전까지 완료로 표시하지 않는다. 파일이나 오브젝트가 있다는 사실만으로 동작을 확인했다고 판단하지 않는다.

## 5. 우선순위 및 범위 변경

1. **필수:** 자동 전진, 반복 상승, 활공, 기본 사격, 장애물·적을 통한 핵심 조작 검증.
2. **필요 시 추가:** 플레이 테스트에 필요한 최소 재시작, 안내 UI와 효과음 등.
3. **후순위:** 증강, 정식 보스, 복수 스테이지, 아이템과 추가 콘텐츠.
4. **장기 검토:** 모바일 대응, 랭킹·온라인 기능, 수익화.

범위를 바꾸기 전에 GDD의 핵심 방향과 충돌하는지 확인한다. 게임 규칙이 바뀌면 `GDD.md`, 개발 순서나 진행 상태가 바뀌면 이 문서, 중요한 기술·설계 선택이 확정되면 `Decisions/`의 ADR을 갱신한다.

## 6. 진행 상태 갱신

- 조사나 작업을 실제로 수행한 뒤 해당 체크박스를 갱신한다. 체크박스는 단계 상태를 대신하지 않는다.
- 단계 상태를 `완료`로 바꾸려면 완료 조건과 필수 검증 근거를 확인한다.
- 구현만 되었거나 실행 검증이 남았으면 `검증 대기`로 둔다.
- 테스트에 실패하면 문제와 재검증 항목을 기록한다.
- 확인된 사실은 근거 없이 삭제하지 않는다.
- 날짜가 필요한 기록은 `YYYY-MM-DD` 형식을 사용한다. 일회성 로그와 오류는 로드맵에 누적하지 않는다.
