# Wing it! — 테스트 및 검증 기준

> **기획 기준:** [GDD.md](GDD.md), 2026-11-06
> **적용 범위:** 코드·씬·에셋 변경과 새 2D 플랫포머·보스전 프로토타입
> **주의:** 아래는 예정된 테스트다. 기재된 기능이 구현되었거나 통과했다는 뜻이 아니다.

## 1. 결과와 완료 기준

| 결과 | 의미 |
| --- | --- |
| 성공 | 명시한 조건을 실제로 실행·관찰해 기대 결과와 일치함 |
| 실패 | 실행했으나 기대 결과와 다름. 재현 조건과 실제 결과를 기록 |
| 미검증 | 실행하지 않았거나 결과를 확인할 근거가 없음 |

정적 검토, Unity 컴파일·Console 확인, Play Mode 직접 조작을 구분해 보고한다. 코드나 씬의 존재, 컴파일 성공만으로 기능을 `성공`으로 표시하지 않는다. 기능을 완료하려면 관련 Play Mode 동작과 영향받는 기존 기능을 확인한다. 문서만 바꾼 작업에는 실행 테스트를 강제하지 않는다.

## 2. 변경 후 기본 검증 절차

1. 변경 전 작업 트리, 관련 씬·프리팹·스크립트·Inspector 연결과 `.meta`/GUID를 확인한다.
2. 코드의 입력·충돌·참조·null 가능성과 새 기획과의 일치 여부를 정적 검토한다.
3. 가능한 경우 Unity에서 임포트·컴파일이 끝날 때까지 기다리고 Console의 신규 `Error`와 관련 `Warning`을 확인한다.
4. 적절한 씬을 Play Mode로 열어 실제 입력과 화면·충돌 결과를 관찰한다. 시작, 반복, 경계 상황을 확인한다.
5. 바뀐 기능과 연결된 기존 동작을 다시 시험한다. 실패하면 원인과 재현 조건을 기록하고 수정 후 같은 절차로 재검증한다.

실행 테스트 결과에는 날짜, Unity 버전, 씬, Editor/빌드 환경, 조작 순서, 기대 결과와 실제 결과를 남긴다. 확인할 수 없는 값은 추측하지 않는다.

## 3. 새 기획의 기능별 검증 계획

세부 조작과 수치가 미정인 경우 먼저 GDD의 해당 규칙을 정하고 기대 결과를 구체화한다. 임시값은 테스트용이라고 표시한다.

### 새 2D 프로젝트 기반 확인

`Assets/Scenes/SampleScene.unity`를 열고 Orthographic 카메라와 `Global Light 2D`가 있는지 확인한다. `Assets/Settings/Renderer2D.asset`이 `UniversalRP.asset`에 연결되어 있는지, Unity 임포트·컴파일 뒤 Console에 실행을 막는 오류가 없는지 확인한다. Play Mode에서 기본 씬이 표시되는지 직접 관찰한다. 이 검증은 2D 프로젝트 기반에만 해당하며 아래 게임플레이 기능의 성공으로 간주하지 않는다.

| 대상 | 시험 방법 | 통과 기준 | 함께 확인할 항목 |
| --- | --- | --- | --- |
| 좌우 이동 | 새 플랫포머 시험 씬에서 왼쪽·오른쪽으로 이동하고 입력을 놓음 | 양방향 이동과 정지가 의도대로 작동 | 카메라, 지형 경계, 반대 방향 전환 |
| 일반 점프 | 접지 상태와 공중에서 점프 입력 | 확정된 점프 규칙에 따라 상승·착지하며 지형을 관통하지 않음 | 연속 입력, 천장, 블록 접촉 |
| 펫 모드 | 플레이어가 이동·점프하고 멈춤 | 작은 새 펫이 정해진 규칙대로 동행 | 거리 변화, 카메라 밖 이동, 변신 복귀 |
| 블록 전환·배치 | 확정된 방식으로 펫을 블록으로 전환·회수 | 설치 가능 조건과 충돌이 정해진 규칙과 일치 | 중복 생성, 지형 겹침, 접근 불가 위치 |
| 블록 발판 | 블록 위에 올라 점프해 높은 곳에 도달 | 블록을 밟아 지형 돌파가 가능 | 플레이어·블록 크기, 밀림, 가장자리 |
| 블록 장애물 돌파 | 블록을 이용해 한 장애물 구간 진행 | 정해진 경로로 구간 통과 가능 | 블록 회수 불가·진행 막힘 |
| 보스전 변신·탑승 | 보스 구간 진입 후 전환 | 펫이 탑승 형태가 되고 플레이어가 전투 상태로 진입 | 전환 중 입력, 위치·카메라, 복귀 |
| 라이딩 슈팅 | 확정된 이동·공격 규칙으로 보스 상대 | 이동·발사·피격이 규칙대로 작동 | 화면 경계, 탄환·보스 충돌 |

**조작감 평가:** 좌우 이동과 점프가 직관적인지, 블록을 언제·어디에 써야 할지 이해되는지, 블록 사용이 지형 문제 해결에 의미가 있는지, 보스전 탑승과 슈팅이 분명한 역할을 갖는지 직접 플레이로 확인한다. 구체적인 합격 수치나 점수는 아직 정하지 않았다.

## 4. 이전 기획 시험 자료

기존 자동 전진·반복 상승·활공·전방 180도 조준·기본 사격·적·장애물 시험은 **과거 프로토타입의 검증 대상**이었다. 현재 기획의 완료 기준이나 필수 회귀 항목이 아니다. 관련 스크립트와 씬이 변경·삭제된 작업 트리이므로 이전 Play Mode 결과를 현재 결과로 재사용하지 않는다.

### 종이비행사 스프라이트 시험 씬

사용자가 추가한 이전 시험 절차는 GitHub에서 제외한 로컬 `Art/LegacyUnityProject-2026-11-06.zip`에 보관된 `WingItSpriteReplacement.unity`와 `PaperPilotSpriteTest.unity`에 대한 것이다. 이전 절차에서는 스프라이트 달리기, 짧은 `Space` 입력의 `jump` 프레임과 상승, 0.3초 이상 입력의 `glide` 프레임과 느린 하강, Console 오류를 확인했다. **두 씬은 현재 활성 `Assets`에 없고, 이 조작은 현행 GDD의 규칙이 아니다.**

## 5. 도구와 결과 보고

- Unity MCP나 Editor가 제공하는 기능만 사용한다. 연결만으로 Play Mode 관찰까지 가능하다고 가정하지 않는다.
- Unity Test Framework는 자동화 가치가 있는 규칙이 확정되었을 때 도입한다.
- Editor를 사용할 수 없으면 정적 확인 범위를 밝히고 컴파일·기능·회귀 테스트는 `미검증`으로 남긴다.
- 오류를 보고할 때 원문 메시지, 위치, 한국어 원인 설명, 재현 단계, 수정 및 재검증 결과를 구분한다.

결과 보고 예시:

```text
- 수정 파일·내용:
- 정적 검토: 성공 / 실패 / 미검증 — 근거
- 컴파일·Console: 성공 / 실패 / 미검증 — 근거
- 기능 테스트: 성공 / 실패 / 미검증 — 씬·입력·실제 결과
- 회귀 테스트: 성공 / 실패 / 미검증 — 확인 범위
- 남은 문제·사용자 확인 사항:
```

실제 진행 상태는 [ROADMAP.md](ROADMAP.md)에, 합의된 게임 규칙은 [GDD.md](GDD.md)에 기록한다. 일회성 로그는 이 문서에 누적하지 않는다.
